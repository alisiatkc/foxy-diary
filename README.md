# FOXY 🦊 — дневник тренировок

Персональное PWA-приложение: календарь на 14 дней, шаблоны тренировок, журнал подходов, сравнение с предыдущей тренировкой, оценки сложности, комментарии, измерения, ручные показатели Apple Watch, импорт CSV и резервные копии JSON.

**Приватность:** репозиторий содержит **только код и шаблоны**, а реальные записи (вес, цикл, тренировки) остаются в локальном хранилище браузера. Никогда не коммитьте резервные копии и архивы Flo в публичный репозиторий.

## Публикация на GitHub Pages
Settings → Pages → Build and deployment → Deploy from a branch → `main` → `/(root)` → Save.
Адрес после публикации: https://alisiatkc.github.io/foxy-diary/

На iPhone: Safari → Поделиться → «На экран „Домой“».

## Важно
Это прототип без аккаунта и серверной базы. Для сохранности используйте «Экспорт JSON», особенно перед очисткой Safari. Автоматической связи с Apple Health и Flo сейчас нет; можно вводить показатели вручную или импортировать подготовленный CSV.

Формат CSV: `date,type,value,source,note` — например `2026-11-14,weight,63.9,Домашние весы,`.

## FOXY 0.5 — отчёты и исторические данные

В отдельной вкладке **«Отчёты»** выбери программу и до четырёх завершённых тренировок. Сравнение отображается по упражнениям и датам. Кнопка **«Сохранить картинку PNG»** создаёт изображение непосредственно на телефоне без отправки данных на сервер.

В редакторе каждого подхода показывается предыдущий **завершённый** результат из истории.

### Импорт ранее записанных тренировок

Исторические данные **не входят в этот публичный репозиторий**. Получи личный файл `FOXY_private_history_2026-11.json` из беседы с ассистентом, перейди в «Данные» → «Импорт исторических тренировок», выбери файл. Импорт безопасно объединяет записи по стабильным идентификаторам и не удаляет существующие.

В подготовленном файле:
- Фул 1: 03, 05, 07 ноября 2026 — данные сравнительной таблицы пользователя;
- Фул 2: 10 ноября — GymGoal файл тренера, 12 ноября — результаты пользователя;
- Apple Watch: 09–13 ноября 2026; 13 ноября — неполный день;
- вес 11 ноября — из переписки;
- данные Flo/InBody не импортируются без подтверждённых источников.

Приблизительные повторы (`≈20`, `12–15`, `13–14`) сохраняются **как текст**, без подстановки выдуманного числа.

### Будущая облачная база

В `supabase/migrations/001_foxy.sql` подготовлена схема PostgreSQL с авторизацией и RLS. **Пока не применена:** нужен подключённый проект Supabase. Не размещай service_role ключ в GitHub или браузере. Подключать синхронизацию будем только после настройки авторизации и проверки приватности.

## Supabase — настройка облачного сохранения (экспериментальная функция)

1. Создайте собственный Supabase project в личном аккаунте.
2. В SQL Editor этого проекта примените `supabase/migrations/001_foxy.sql` (схема с RLS — доступ только владельцу).
3. В Authentication включите **Email + Password**. Проверьте настройки подтверждения email.
4. В FOXY → «Данные» → «Облако · Supabase» введите **Project URL** и **Publishable API key** (или legacy anon key). Никогда не вводите `service_role` или Secret API key в браузере.
5. Зарегистрируйтесь, подтвердите почту при необходимости, войдите.
6. Нажмите «Сохранить копию в облаке». Пока это **ручное** сохранение целого снимка базы FOXY (программы, календарь, тренировки, измерения). «Загрузить из облака» сначала выгружает резервную копию текущих локальных данных, затем заменяет их облачной копией.

**Внимание:** не проверяйте облако на единственной копии важных данных; сначала экспортируйте JSON. Не подключайте облачную синхронизацию, пока SQL-политики RLS не применены. Для первой версии сервис остаётся доступным и без Supabase с локальным сохранением.

Не следует добавлять личный JSON-архив тренировок или данные Flo/InBody в публичный репозиторий.
